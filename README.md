# DatasetSherlock

Phase 1: a static React + TypeScript shell, created with the official Vite
`react-ts` template and simple CSS. File selection and dataset processing are
left for your learning exercises.

## Commands

Run commands from `D:\Me\VitAuditor\dataset-sherlock`:

```powershell
npm install
npm run dev
```

- `npm install` installs the packages in `package.json`. Dependencies are already
  installed here. Use `npm ci` for a clean install of the locked versions.
- `npm run dev` starts Vite's development server. Open the printed URL. Saving
  source files updates the browser. Stop the server with Ctrl+C.
- `npm run build` checks TypeScript (`tsc -b`), then creates production files in
  `dist/` using Vite. Type errors stop the command before bundling.
- `npm run lint` checks common code mistakes using Oxlint, included by the template.
- `npm run preview` serves the last production build locally for inspection.

The initialization command was:

```powershell
npm create vite@latest dataset-sherlock -- --template react-ts --no-interactive
```

`react-ts` chooses React with TypeScript. The extra `--` forwards the remaining
options through npm to the scaffold tool.

## Architecture and file guide

```text
index.html
  src/main.tsx
    App
      AppHeader
      main
        Dashboard
          DatasetUpload
          AuditFindings
```

| File | Responsibility and reason it exists |
| --- | --- |
| `index.html` | Browser entry document, title, mobile viewport setting, and the empty `root` element React fills. |
| `src/main.tsx` | Connects React to that root, loads CSS, and renders `App` inside `StrictMode` for extra development checks. |
| `src/App.tsx` | Composes the header and main content into the application shell. |
| `src/components/AppHeader.tsx` | Product name and navigation links to sections on this page. |
| `src/components/Dashboard.tsx` | Dashboard heading and composition of the two feature sections. |
| `src/components/DatasetUpload.tsx` | Static dataset placeholder and the home of your first exercise. |
| `src/components/AuditFindings.tsx` | Static findings placeholder, kept separate for later work. |
| `src/index.css` | Shared typography, spacing, and responsive layout: stacked sections on small screens, two columns from 760px. |
| `package.json` | Project name, scripts, and runtime/development dependencies. Only React and React DOM are runtime dependencies. |
| `package-lock.json` | Exact resolved dependencies for repeatable installs. Generated by npm; do not edit manually. |
| `vite.config.ts` | Enables Vite's React integration and development updates. |
| `tsconfig.json` | Connects the application and tooling TypeScript configurations. |
| `tsconfig.app.json` | Strict TypeScript checks for browser code and JSX support. |
| `tsconfig.node.json` | Strict TypeScript checks for the Vite configuration, which runs in Node.js. |
| `.oxlintrc.json` | Linter rules supplied by the Vite template. |
| `.gitignore` | Keeps dependencies, build output, logs, and local editor files out of Git. |
| `README.md` | Documents setup, architecture, and the current exercise. |

`node_modules/` contains installed dependencies and `dist/` contains generated
build output. Neither is application source. Starter images and demo CSS were
removed because this shell does not need them.

## React concepts used here

- A **component** is a function returning JSX, the HTML-like syntax in `.tsx`
  files. Its name starts with a capital letter so React recognizes it.
- **Composition** means putting components together, such as `Dashboard`
  rendering `DatasetUpload` and `AuditFindings`. Each file has one clear job.
- The `<>...</>` wrapper in `App` is a **Fragment**: it groups elements without
  adding an extra HTML element.
- **State** is component memory. Updating state asks React to render again so the
  UI reflects the new value. Changing a normal local variable does not do this.
- **Props** pass information from a parent to a child. This static shell does not
  need them yet. Local state will be sufficient for your first exercise.
- Navigation uses normal HTML fragment links (`#dataset-upload`), so this single
  page does not need a routing library.

## Exercise 1: select image files using React state

Work only in `src/components/DatasetUpload.tsx`.

1. Replace the placeholder box with a labeled file input. Allow multiple files
   and use `accept="image/*"` as the browser's image selection hint.
2. Use React's `useState` to store the selected files as a `File[]`, initially empty.
3. In the input's change handler, copy its `FileList` into an array and update
   state. Handle a missing file list safely.
4. Show an empty message when state is empty. Otherwise show the selected file
   count and each filename. Derive the count from the files array.
5. Choosing another set should replace the current selection.

Hints: `event.currentTarget.files` gives you the browser file list;
`Array.from` converts an array-like list. Use a stable key when rendering a list.
The `accept` attribute is a picker hint, not complete file validation.

Check the initial empty message, selection of several images, and replacement
with a different set. Then run `npm run build` and `npm run lint`.

Keep the exercise local to the component. Upload requests, previews, drag and
drop, analysis, and persistent storage belong to later steps. Implement it
yourself, then share the code for review before starting another exercise.
